# expert-review

OMPの現在のセッションをそのまま引き継ぎ、設定済みの高性能モデルへ敵対レビューを依頼し、元のモデルが指摘を査定して必要な反映まで行う拡張です。

通常作業を高コストモデルで続けたり、`/review` のレビュー用サブエージェント群を起動したりせず、設計・実装の最後だけ独立した強いモデルへ確認させる用途を想定しています。

## 動作

`/expert-review` を実行すると、現在のモデル、thinking level、利用中ツールを退避してから次を行います。

1. `modelRoles.advisor` に設定したモデルへ一時切替
2. thinking levelを `modelRoles.advisor` の `:思考レベル` 接尾辞へ切替（明示がなければ元の thinking を維持）
3. 利用可能ツールを `read` / `grep` / `glob` のみに制限
4. 現在の会話コンテキストを対象に、敵対レビュー用プロンプトを1回だけ送信
5. レビューターンが最終的に完了した時点で、元のモデル、thinking level、利用可能ツールへ復元
6. 復元に成功した場合だけ、元のモデルへ査定用フォローアップを1回だけ送信
7. 元のモデルがレビュー指摘を独立に査定し、成立する指摘だけ最小変更で反映し、変更に関連する必要な検証を実行

レビュー結果を無条件で適用しません。最終的な採否判断と変更責任は元のモデル側にあります。重大な懸念がない場合や、採用すべき指摘がない場合は変更を作りません。

レビュー中は `tool_call` フックでも上記3ツール以外を遮断するため、`task`、サブエージェント、オーケストレーション、書き込み系ツールは利用できません。元のモデルへ戻った後は、退避した利用中ツールを復元するため、通常の実装と検証ができます。一時切替が途中で失敗した場合は復元して終了し、フォローアップは送りません。レビュー中にセッション切替、branch、tree、shutdownが発生した場合も復元を試みますが、自動修正ターンは開始しません。自動再試行やコンテキスト圧縮などで継続が予定されている間はレビュー状態を維持し、最終完了時に復元します。復元の一部でも失敗した場合はフォローアップを送らず、安全に停止します。フォローアップで起動した元のモデル側ターンが終わっても、再度フォローアップは送りません。実行中に再度呼び出された場合は警告だけ出し、状態は変更しません。

このプラグインはOMP本体のAdvisor watchdogを有効化しません。現行のAdvisorは有効化後のprimary transcript更新を継続的にレビューする用途で、セッション途中から有効化した場合は過去の会話全体を最初から再レビューしません。`expert-review` は、任意の時点で**それまでに蓄積した現在の会話コンテキスト全体を1回だけ**別モデルへ査読させ、直後に元モデルへ戻す用途に限定します。高コストなreviewerを常時動かしたくない場合にも向きます。

`modelRoles.advisor` はレビュー用モデルを指定する既存設定欄としてだけ利用します。

## 設定

レビューに使う高性能モデルを `modelRoles.advisor` で指定します。例としてAstraを使う場合は次のように設定します。Astraへの固定依存ではなく、差し替え可能な一例です。

```yaml
modelRoles:
  advisor: openai-codex/gpt-6-astra:xhigh
```

レビュー時の thinking level は `advisor` 値の `:思考レベル` 接尾辞から解決します。接尾辞がない場合、`auto`、`inherit` の場合は元の thinking を維持します。
将来モデルを差し替える場合は `modelRoles.advisor` だけ変更します。コマンド名や処理手順は特定モデル固有ではありません。

## 使い方

```text
/expert-review
```

重点確認事項も追加できます。

```text
/expert-review rollback と production migration の成立条件を重点確認
```

レビュー用モデルには、現在のコンテキストにある設計・実装について、誤った前提、要件漏れ、矛盾、不要な複雑性、現実的な失敗条件、連携・互換性リスク、検証不能な完了条件を重大度順に確認させます。具体的な破綻条件または根拠のある指摘だけ返し、確認できない事項の断定や好みの設計差の欠陥扱いをしないように指示します。各指摘は重大度、問題、成立条件や根拠、影響、最小の修正または判断の粒度で返します。

レビュー結果だけ欲しい場合は `--review-only` を使います。この場合はレビュー完了後の復元で停止し、自動フォローアップは送りません。

```text
/expert-review --review-only
/expert-review --review-only rollback の成立条件を重点確認
```

`--review-only` は重点確認事項の前後どちらに書いてもよく、本文には混入しません。

## Orca

通常のOMPスラッシュコマンドとして動作するため、Orca上のOMPターミナルでも `/expert-review` をそのまま実行します。Orcaワーカーや別セッションを起動する処理はありません。

## インストール

```bash
omp plugin marketplace add https://github.com/unitea1992/omp-extensions
omp plugin install expert-review@omp-extensions
```

拡張の更新後はOMPを再起動してください。

## 制約

- thinking levelは `modelRoles.advisor` の `:思考レベル` 接尾辞から解決します。接尾辞がない場合、`auto`、`inherit` の場合は元の thinking を維持します。
- レビュー用モデルは `modelRoles.advisor` から解決します。解決できない場合は何も変更せず終了します。
- レビューターン自体は現在のメインセッション上で実行されるため、それまでのセッション内容を参照できます。
- 開始時のthinkingが `auto` の場合、復元されるのは解決済みの具体的な段階です。現在のExtension APIでは `auto` そのものへ戻せません。
- レビュー側は `read` / `grep` / `glob` のみで、書き込み、編集、実装、`task`、サブエージェントは行いません。
